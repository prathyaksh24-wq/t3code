# Roadmap

The roadmap describes product direction, not delivery promises. Detailed work lives in GitHub Issues.

## Now

- Run the local one-to-three-user beta and record per-machine provider qualification results.
- Choose the standalone product name and finish the fork-owned visual identity.
- Review upstream T3 Code updates through isolated integration branches.
- Turn beta feedback into focused reliability and usability issues.

## Next

- Add automatic retention controls and disk quotas without deleting dirty worktrees.
- Package and sign the fork-owned desktop beta after the web workflow is stable.
- Refine the OpenCode terminal-oriented workflow while retaining native provider CLIs.
- Add beta-user access and support controls without turning the local data root into shared multi-tenant storage.

## Later

- Add multi-pane and multi-agent orchestration after workspace isolation is proven.
- Add structured cross-runtime handoff without claiming provider-session portability.
- Evaluate a hosted control plane only after tenancy, quotas, retention, and privacy boundaries are designed.

## Completed foundation

- Separated the fork from Vellum application data, runtime configuration, memory, and release ownership.
- Preserved T3 Code's typed client/server contracts and existing Codex, Claude Code, Cursor, Grok Build, and OpenCode adapters.
- Shipped the web-first shell, projectless chats, runtime and model management, streamed conversations, approvals, cancellation, diagnostics, terminal, diffs, and workspace leases.
- Added provider qualification, local beta operations, unsigned Windows artifacts, and browser/performance capture gates.
